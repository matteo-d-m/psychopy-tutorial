# Chapter 0: Prerequisites

To follow a tutorial on PsychoPy, it is imperative to know what it is:

:::{note} Definition
PsychoPy ([Peirce et al., 2019](https://doi.org/10.3758/s13428-018-01193-y)) is a Python library to program psychological experiments. Like many Python libraries, PsychoPy is free, open source, and the result of a large-scale collaborative effort.
:::

## 0.1. Terminology
In practice, _Python library_ means that PsychoPy is a folder containing all the code you might need to run a cognitive or behavioural experiment. However, navigating the world of PsychoPy requires a more precise definition of _library_ and of two related terms: _module_ and _package_.

### 0.1.1. Module
In Python jargon, a file that contains code to carry out specific tasks is a _module_. For example, one could take all the code that could ever be needed to draw rectangles and save it into a Python file called `rectangles.py`: that would be a module &mdash; specifically, a rectangles-drawing module.

### 0.1.2. Package
Collections of modules that carry out related tasks are called _packages_. For example, one might take a number of geometry-drawing modules (one for each geometric figure of interest) and save them into a folder called `geometry/`: that would be a package. 

### 0.1.3. Library
Finally, collections of packages that can interact to serve a higher purpose are called _libraries_. For example, one might take the `geometry/` package and put it in the same directory as other packages: a stimulus timing package, a response collection package. etc. That would be a library. 

PsychoPy is a collection of packages, so it is a library. It contains a number of different packages, each serving a specific function through multiple modules. For the purpose of an experiment where subjects watch stimuli on a screen, the package of interest is called `visual`.

```bash
psychopy/           # a library containing multiple packages
├── package1
├── package2
├── package3
├── ...
└── visual          # a package for drawing visual stimuli
    ├── file1.py    # a number of files serving specific, interrelated functions
    ├── file2.py
    ├── file3.py
    ├── ...
    └── fileN.py
```

## 0.2. Installing PsychoPy
When you install PsychoPy from the official website, you are prompted to install the PsychoPy Standalone Version (SPV) &mdash; which, on top of the package code, installes a code editor called Coder, a graphical user interface (GUI) called Builder (where you can build experiments by pointing-and-clicking), and a dedicated terminal/process manager called Runner. The SPV is indicated for people who cannot or do not want to write their own experiment code and would thus use the Builder. The [official PsychoPy website](https://psychopy.org/) has plenty of tutorials on the Builder and interested users can refer to those.

:::{note}
This website focuses on programming a visual neuroscience experiment using only code, without ever referring to the Builder. 
:::

The SPV is useless for people that want to write their own code. This is why the SPV provides the Coder &mdash; which, however, is much less powerful and user-friendly than widely available alternatives like VSCode, Spyder, or PyCharm. In the author's experience, the best way to use PsychoPy is to install it through `pip` and code the experiment in the VSCode editor. 

:::{aside}
`pip` is a package manager (that is, software that manages the installation and harmonisation of other software) that is automatically installed alongside Python. Assuming you have Python (and thus, `pip`) in your computer, you can open a terminal and installa PsychoPy by running the following command: `python -m pip install psychopy`. If you don't have Python, you can install it from the official website ([python.org](https://www.python.org/)) and then do `python -m pip install psychopy`. 
:::

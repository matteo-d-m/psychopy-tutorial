# Chapter 3 &mdash; Representing Different Experimental Conditions 

In neuroscientific experiments, we usually study how a subject responds to some stimulation (sensory, emotional, magnetic, electrical, etc.). For statistical power, we want to measure the same response several times. Therefore, we want an experiment with multiple _trials_: stereotyped, repeated presentations of the same stimulus or stimulus sequence. 

We also want to study how a subject responds to different _kinds_ of stimulation (e.g., seeing a square vs. seeing a circle). Therefore, we want an experiment with multiple _conditions_: variations of the stimulus or stimulus sequence presented to the subject in any given trial.

Given these requirements, we need code to:
- Define different conditions
- Administer each condition for multiple trials
    - The number of trials per condition will vary depending on our design: balance
- Administer the conditions in the order that we want 
    - That's often random

## 3.1. The Conditions File

In PsychoPy, you need to define your conditions in an external `.csv` file that has one row per condition and one column per condition parameter. For example, the following example describes four conditions determined by the presence (1) vs. absence (0) of a stimulus and by its colour:

| presence | colour |
|----------|--------|
| 1        | black  |
| 1        | yellow |
| 0        | black  |
| 0        | yellow |

If you want to give higher weight to one condition (i.e., present it more times than others), you can put it in multiple rows. For example, the following table doubles the weight of the condition where the stimulus is present and is black:

| presence | colour |
|----------|--------|
| 1        | black  |
| 1        | black  |
| 1        | yellow |
| 0        | black  |
| 0        | yellow |

## 3.2. The importConditions Function

In every experiment, each trial belongs to one condition &mdash; that is, one row of the conditions file. Therefore, PsychoPy implements trials as iterations over the file's rows. To do so, it reads the file and it transforms it into an iterable<sup>1</sup> (i.e., a Python object that you can iterate over). This is done by the `importConditions` function from package `data`, as shown by the code below:

```{margin}
<sup>1</sup> From the RealPython.com definition (accessed on 12 May 2026 &mdash; [source](https://web.archive.org/web/20260512162952/https://realpython.com/ref/glossary/iterable/)):

_"In Python, an iterable is an object that can return its elements one at a time, allowing you to loop over it using a for loop or any other iteration tool. Technically, an iterable must implement the `.__iter__()` special method which returns an iterator, or implement `.__getitem__()` to support indexing. Common built-in iterables include lists, tuples, strings, dictionaries, and sets"_
```

```python
from psychopy import data

CONDITIONS_FILE_NAME = "conditions.csv"
my_conditions = data.importConditions(CONDITIONS_FILE_NAME)
```

## 3.3. The Trial Handler Class

The output of `data.importConditions` is meant to be the input to `data.TrialHandler`, a class `TrialHandler` that implements methods to:
- Iterate over conditions (as read by `data.importConditions`)
- Do it as many times as you want (one trial per condition vs. multiple trials per condition)
- Do it in the order you want (sequential vs. random)

The code below instatiates a TrialHandler object that represents a set of conditions (that is, the contents of the conditions file as represented by `my_conditions`, itself the output of `importConditions`) and the instruction to iterate them once (`nReps=1`) in a random order (`method="random"`).

```python
my_trials = data.TrialHandler(trialList=my_conditions, 
                              nReps=1,
                              method="random")
for trial in my_trials:
    # do things, e.g., present stimuli and collect responses
```

:::{note} **Pay attention the the `method` argument**

You will probably want to pass `random`. This will shuffle the conditions, and all conditions will be guaranteed to occur once before the second repeat.

Alternatively you could pass `fullRandom`, but be aware that all the repetitions of one condition might occur before any other. 

Finally, you could pass `sequential` to present all conditions in the exact order that they appear in the conditions file.
:::
